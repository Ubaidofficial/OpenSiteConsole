## OpenSEO and AI agents

- **Sign in from a connector (claude.ai, Claude Desktop, ChatGPT-style clients that use OAuth):** no key to paste. In Claude: *Customize → Connectors → Add custom connector*, URL `https://<your-address>/api/mcp`, Authentication **Sign in now**, and if it asks how Claude identifies itself choose **Register automatically**. Click Connect: your browser opens SEOConsole's approval page, you sign in (as the owner or an admin: approving creates an API key), choose all sites or some, and Allow. The app gets a read-only token that renews itself (access token 1 hour, refresh token 60 days unused) and shows up on the Agents page with a "sign-in" tag; **Revoke** cuts it off. This is a small OAuth 2.1 server built into the app (dynamic client registration, PKCE S256, rotating refresh tokens; the discovery documents are at `/.well-known/oauth-protected-resource` and `/.well-known/oauth-authorization-server`). Only Claude's callback (`https://claude.ai/api/mcp/auth_callback`) and local loopback addresses may register by default; allow another client's exact https callback with `MCP_OAUTH_REDIRECTS`. It was tested against a simulated client and a real browser, **not yet against the real claude.ai**. The public address must be https and reachable from the internet.
- **Agents page** → create an API key (optionally limited to some sites) → add SEOConsole as an MCP server next to OpenSEO's. For Claude Code, run the command shown there in a terminal **on your own computer** (not in a cloud session), then check it with `claude mcp list`. By default it is available only in the folder you ran it in; add `--scope user` right after `mcp add` to use it in every project (per Claude Code's documentation, user-scope servers live in `~/.claude.json`, which the desktop app's Code tab also reads). The key is a bearer token that is shown once: keep it private and delete it on the Agents page if it leaks. Sixty-two tools: forty-two only read (every connected source: Search Console, GA4, Tag Manager, Bing, Clarity, Core Web Vitals, OpenSEO link, and every analysis below: trends, content groups, SEO tests, indexing, on-page, internal-link suggestions, AI traffic, the action queue, the weekly digest, sitemap coverage, IndexNow and Google updates, almost all answered from stored data) and twenty change things (see the three levels below). Each change tool refuses unless that key or sign-in has the level it needs, and is refused when `READ_ONLY=1`. The ones that change things in the app itself (`mark_action`, `log_change`, `start_seo_test`, `set_brand_terms`, `sync_site`, `read_sitemaps`, `run_onpage_check`, `submit_indexnow`, `watch_urls`) act on URLs of that site only, are limited to 30 a minute per key, and are written to the audit log with the key's name; the Agents page shows that log. Nothing can delete your data, connect or disconnect accounts, create keys, or touch credentials: those stay in the app. Three tools reach Google live: `get_sitemaps` (Google's own sitemap status), `inspect_url` (URL Inspection for up to 5 URLs of the property; answers are reused for 12 hours, `refresh` spends URL Inspection quota) and the sync itself. `get_page_insights` returns the same combined per-page view as the Pages tab (below). `get_performance` answers questions like "mobile in the US last month against the month before": one dimension (query, page, country, device or date), any date range, an optional comparison window (a change is only claimed when the stored history covers it), and country, device and text filters. The **Agents** page has copy-paste setup for Claude Code, Claude (custom connector with a header credential), Codex and generic clients; ChatGPT's connectors are reported to expect OAuth, which this server does not implement, so it may not work there (unverified). `get_connections` tells an agent which sources are connected, and `get_tracking_health` cross-checks Search Console, GA4 and Tag Manager.
- **Three levels of key, read-only by default.** *Read only* sees everything and changes nothing. *Submit* (Agents page, or the level chosen when signing in a connector) can also use the nine tools that change things inside the app (listed above) and send URLs and sitemaps to search engines and set things up: `submit_urls_for_indexing`, `submit_sitemap`, `inspect_and_submit_urls`, `run_indexing_check`, `setup_indexnow`, `build_request_indexing_queue`, `mark_indexing_requested`, `get_site_verification_token` and `verify_site_ownership`. *Submit and delete* adds the two things that cannot be undone by calling the tool again, `delete_sitemap` and `cancel_indexing_queue`, and those take **two calls**: the first changes nothing and returns what would go plus a single-use `confirmation_token` (10 minutes, this key, this site, this target); only a second call that presents it does the work. That stops one mistaken or injected call from deleting anything and puts a pause where a person can look; it does not prove a person agreed, because an agent with a delete key can make both calls, which is why that level is separate and never the default. Submitting is limited per key per day, respects `READ_ONLY=1` (which grants only read keys), is written to the audit log, and a site-limited key cannot use the account-level tools. `cancel_indexing_queue` (throws away the queued URLs) is the other delete tool. `submit_urls_for_indexing` takes `drip_days` and `queue_overflow`. `inspect_and_submit_urls` inspects up to 20 URLs and then submits the ones that are not indexed and not blocked, in one call; the Request list tools build and record that list (the button itself cannot be pressed through any API). Read-only tools include `get_submission_status` (with the day 5 verdict and the queue), `get_indexing_quotas`, `get_request_indexing_queue`, `get_sitemap_lastmod_health`, `get_quick_wins`, `get_internal_link_suggestions`, `suggest_indexing_candidates` and `check_sitemap`. The tool definitions every client loads at the start of a session are kept under about 33 KB (a test enforces it), down from 38 KB; shortening further would mean loading tools on demand, which is not built.
- Connect OpenSEO on the Connect page and each site is linked to its OpenSEO project by domain. An agent calls `get_openseo_project` to obtain the project id, then uses OpenSEO's own tools (keyword research, rank tracking, audits) on it — first-party history from here, third-party data from there.
- **Working with OpenSEO** (once a site is linked; tool names and shapes read from OpenSEO's source on 2026-11-08, tested against a fake built from it, and checked against a live self-hosted OpenSEO the same day: tool schemas and real answers of `list_projects`, `get_rank_tracker`, `estimate_rank_tracker_cost`, `get_audit_issues` and `get_keyword_metrics`; adding keywords and creating a tracker were not exercised live, to leave the account unchanged): **search volume** on the Queries tab (*Show search volume*: your top searches by impressions, up to 700 at a time and 80 characters each, through OpenSEO's `get_keyword_metrics`; it spends OpenSEO credits, so it only runs when you press it, and each search is asked again after 30 days; Volume and KD columns then appear on Queries and on Opportunities' striking-distance list). **Rank tracking** on the Opportunities tab (*Track striking-distance searches in OpenSEO*: your best non-brand searches at positions 4-20, up to 100 at a time, sent to the project's tracker for this domain; *Preview* shows OpenSEO's own cost estimate and changes nothing; with no tracker one is created as **manual**, which has no recurring cost; adding to a **scheduled** tracker passes OpenSEO the per-check credit ceiling the preview showed, as OpenSEO requires, and OpenSEO refuses if the real cost is higher; adding keywords spends no credits by itself, checks do; searches sent are not offered again). **Site audit** on the On-page tab and in the action queue: OpenSEO's latest audit is read once a day (`get_audit_issues`, free: it reads stored results and runs no audit), and its critical and warning issues on pages that earn clicks become *OpenSEO audit* items with OpenSEO's own fix; run new audits in OpenSEO. Fetching volume and sending searches are refused when `READ_ONLY=1`.
